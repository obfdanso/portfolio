## Context

bitby is a **UI reconstruction study**: an independent learning project that
rebuilds the interface patterns of the Binance mobile app.
It is **not affiliated with, endorsed by, or connected to Binance**, reproduces none of their trademarks or logos, and is not a working exchange, with no real market data, no accounts, and no trades.

The reason to rebuild a trading interface is that it is genuinely difficult.
Dense numeric rows, constant updates, tight vertical rhythm, and a hierarchy
that has to survive being read at a glance are harder problems than most CRUD
screens ever pose.

## My role

I built the frontend, including the screens, the navigation, and the list and
chart components.

It is a React Native app. The backend was written in Java by someone else;
the `stack` listed above is deliberately limited to what I actually built,
which is the same rule every project on this site follows.

## Key decisions

**Rebuilding from observation, not from assets.** Working out the spacing, type
scale and hierarchy by eye is what made this a study rather than a copy-paste
exercise, and it is where the learning actually was.

**Treating the market list as a performance problem first.** A list of
constantly-updating numeric rows punishes naive re-rendering, so the row
components were built to update in isolation from the start rather than being
optimised later.

## Outcome, and what I would do differently

Not bundled for distribution, so the demo here is a screen recording rather
than something you can install.

What I took from it was calibration. Matching a production interface by eye
teaches how much of a polished product is spacing and type discipline rather
than features.

While I don't have any major regrets about how it turned out, if I were to build this again today, I would apply much stronger design patterns and architectural knowledge from the very beginning to keep the frontend logic even cleaner.
