## Context

A point-of-sale system serves three people with incompatible needs. A cashier
wants the fastest possible path through a sale. A manager wants stock levels
and takings. An administrator wants control over users and configuration.

Building one interface that serves all three badly is the common failure. This
project treats them as three interfaces over shared data instead.

## My role

I built the frontend: all three role-specific interfaces, the component
structure, and the client-side state.

## Key decisions

**Separate interfaces rather than permission-gated menus.** Hiding the controls
a cashier cannot use still leaves them navigating a manager's information
architecture. Each role gets a layout shaped around its own task instead.

**Speed over completeness on the cashier screen.** That flow runs hundreds of
times a day, so it is keyboard-driven and reachable in the fewest possible
interactions — even where that meant leaving features out of that particular
view.

## Outcome, and what I would do differently

Built as a student project and complete as an interface.

**I would write it in TypeScript.** It is plain JavaScript, and a domain built
on prices, quantities and running totals is exactly where a type system earns
its cost. Porting it is the clearest improvement available.
