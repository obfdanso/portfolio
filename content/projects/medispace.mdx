## Context

Students on campus manage their own medication without the routines a clinic
provides. Doses get skipped, courses get abandoned halfway, and the questions
that would normally go to a pharmacist go unasked.

MediSpace addresses both halves of that: a schedule that tracks what to take
and when, and an AI chatbot for the questions students would otherwise search
for or simply ignore.

## My role

I built the frontend. The interface, state handling, the chat UI, and the
integration against the team's API were mine. I did not write the backend
services.

The team consisted of nine people: four frontend developers, three backend developers, a project manager, and a QA engineer. It was a highly collaborative environment where my previous project experience helped keep our frontend momentum smooth.

## Key decisions

**TypeScript throughout.** Medication data is the kind where a wrong field
rendering silently as `undefined` is a real problem, not a cosmetic one. Typed
models meant a mismatch failed at compile time rather than in front of a
student reading their dose.

**Streaming the chatbot's replies.** A medical question answered after a
five-second blank pause reads as broken. Rendering tokens as they arrive made
the same response feel immediate, without making it any faster.

We initially considered waiting for the full response from the AI API before rendering the message to keep our state management simpler. However, we rejected that approach because a blank pause of several seconds reads as broken to a user expecting a conversational interface. By streaming the response, we significantly improved the perceived performance.

## The hard part

Interestingly, the most time-consuming issue wasn't a traditional code bug, but a deployment gap. When we first hosted the frontend on Vercel, the live site was missing several key features that we had just built and tested perfectly. We initially suspected that Vercel was caching an old build or failing to build our newer components properly.

After spending time debugging the Vercel configuration, the actual cause turned out to be much simpler: I had finished the frontend work locally but had simply forgotten to push the final commits to GitHub. We found it during a group debugging meeting: when we cross-checked the GitHub repository together, I realized my local changes had never been pushed. A quick `git push` resolved the "bug" immediately.

## Outcome, and what I would do differently

Deployed on Vercel and usable by students today.

Overall, the architectural choices held up incredibly well, and I'm very proud of the solid foundation we built together.

If I built it again, the part I would change is the chatbot's interface. The
streaming worked, but the UI around the conversation is where I would spend my
time on a second pass.
